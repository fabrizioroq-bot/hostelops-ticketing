# API Reference

Base URL: `VITE_API_BASE_URL` (local dev: `http://localhost:8000`).

Full interactive documentation (auto-generated by FastAPI from the same
Pydantic schemas used in code) is available at `/docs` (Swagger UI) and
`/redoc` on the running backend.

All endpoints except `/health` require `Authorization: Bearer <supabase_access_token>`,
obtained client-side from `supabase.auth.getSession()` after logging in
through the Supabase Auth JS SDK.

## Auth

| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/auth/me` | any | Current user's profile: id, email, full name, role, assigned hostel IDs |

## Tickets

| Method | Path | Roles | Description |
|---|---|---|---|
| POST | `/tickets` | any (own hostel) | Create a ticket; auto-links/creates the guest golden record, auto-assigns the creator |
| GET | `/tickets` | any (RLS-scoped) | List tickets; query params: `status`, `priority`, `channel`, `reason`, `hostel_id`, `assignee_id`, `date_from`, `date_to`, `search`, `page`, `page_size` |
| GET | `/tickets/{id}` | any (RLS-scoped) | Get one ticket |
| PATCH | `/tickets/{id}` | any (RLS-scoped) | Update status/priority/resolution/recontact; `assignee_id` change requires admin/supervisor |
| GET | `/tickets/{id}/history` | any (RLS-scoped) | Field-level change history |

## Guests (MDM)

| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/guests` | any (RLS-scoped) | List golden guest records; `?search=` filters by name |
| GET | `/guests/{id}` | any (RLS-scoped) | Get one guest |
| GET | `/guests/{id}/tickets` | any (RLS-scoped) | All tickets linked to this guest |
| PATCH | `/guests/{id}` | admin, supervisor | Edit a golden record (e.g. fill in email/phone) |

## Deduplication

| Method | Path | Roles | Description |
|---|---|---|---|
| POST | `/dedup/scan` | admin, supervisor | Run fuzzy-match detection, populate the review queue |
| GET | `/dedup/candidates` | admin, supervisor | List merge candidates; `?status=pending\|approved\|rejected` |
| POST | `/dedup/candidates/{id}/approve` | admin, supervisor | Merge the pair into one golden record |
| POST | `/dedup/candidates/{id}/reject` | admin, supervisor | Dismiss the pair permanently |

## Hostels

| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/hostels` | any | Hostel directory |
| GET | `/hostels/{id}` | any | One hostel |
| POST | `/hostels` | admin | Create a hostel |
| PATCH | `/hostels/{id}` | admin | Update a hostel |

## Users

| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/users` | admin, supervisor | User directory |
| POST | `/users` | admin | Provision a new user (via Supabase Auth Admin API) |
| PATCH | `/users/{id}` | admin | Update role/name/hostel assignments/active status |
| POST | `/users/{id}/deactivate` | admin | Revoke access |

## Dashboards

| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/dashboards/executive` | admin, supervisor | Overview, trend, by-reason, by-channel, priority×status, resolution time, recontact rate |
| GET | `/dashboards/agent` | any | Own performance; admin/supervisor may pass `?agent_id=` for another agent |
| GET | `/dashboards/data-quality` | admin | Dedup/completeness summary + list of incomplete tickets |
| GET | `/dashboards/hostel-performance` | admin, supervisor | Per-hostel volume/resolution time, top issues, agent workload |

All dashboard endpoints accept `hostel_id`, `assignee_id`, `priority`,
`reason`, `date_from`, `date_to` query params where applicable.

## Exports

| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/exports/tickets` | admin, supervisor | `?fmt=csv\|xlsx&columns=a,b,c&status=&hostel_id=&priority=&date_from=&date_to=` |
| GET | `/exports/guests` | admin, supervisor | `?fmt=csv\|xlsx&columns=a,b,c` |

Every export call is recorded in `audit_logs` with the actor, format, row
count, and filters used.

## PMS Integration

| Method | Path | Roles | Description |
|---|---|---|---|
| POST | `/pms/{hostel_id}/credentials` | admin | Store `{provider, access_token, external_id}` for this property |
| POST | `/pms/{hostel_id}/sync` | admin | Pull reservations from the configured PMS, enrich guest golden records |

## Reports

| Method | Path | Roles | Description |
|---|---|---|---|
| GET | `/reports/weekly.pdf` | admin, supervisor | On-demand weekly summary PDF (same content as the scheduled email) |

## Maintenance

Fully separate from the guest-ticketing endpoints above — a different
table, different roles, different storage bucket. Agents have no access
at all; supervisors are view-only.

| Method | Path | Roles | Description |
|---|---|---|---|
| POST | `/maintenance-tickets` | admin, maintenance | Create a maintenance ticket for one of your assigned hostels |
| GET | `/maintenance-tickets` | admin, supervisor, maintenance | List; query params: `hostel_id`, `status_`, `priority` |
| GET | `/maintenance-tickets/{id}` | admin, supervisor, maintenance | Get one ticket |
| PATCH | `/maintenance-tickets/{id}` | admin, maintenance | Update title/description/status/priority |
| POST | `/maintenance-tickets/{id}/photos` | admin, maintenance | Upload one photo (multipart `file`; JPEG/PNG/WebP/HEIC, max 10MB) — call once per photo for multiple |
| GET | `/maintenance-tickets/{id}/photos` | admin, supervisor, maintenance | List photos with short-lived signed URLs |
